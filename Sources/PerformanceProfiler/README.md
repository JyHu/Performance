# PerformanceProfiler

热点方法采样。

## 职责

周期性挂起目标线程取栈，聚合出 Top-N 高频调用栈，定位「卡在哪儿」。

## 主要类型

| 类型 | 职责 |
|---|---|
| `PerfProfilerMonitor` | 监测器，配置见 `PerfProfilerMonitorOptions` |
| `PerfHotspotSample` | 窗口聚合：样本数、Top 栈、采样失败数 |
| `PerfHotStack` | 高频栈：签名、出现次数、占比、代表性帧 |

## 关键设计

- **采样必须由独立线程挂起目标线程**：上一版用 `DispatchQueue.main.async { Thread.callStackSymbols }` 采样——主线程一旦真的忙起来，这个 block 排不上队，于是「热点采样器」只在主线程空闲时采得到样本。想测热点，测到的全是空闲。
- **10ms 间隔是精度与开销的折中**：每次采样都要挂起目标线程，过密会实质影响被观测线程。
- **默认只采主线程**：绝大多数用户可感知的问题出在主线程。全线程采样的开销和数据量高一个量级。
- **采样失败数必须可见**：失败率高说明数据不可信，「Top1 占 80%」可能只是因为总共才采到 5 个样本。
- **占比低于阈值的栈不上报**：低频栈多半是噪声。热点本身定级 `.debug`，是排查材料不是问题结论。
