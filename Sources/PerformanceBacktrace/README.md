# PerformanceBacktrace

跨线程栈回溯 —— 修掉上一版最大 bug 的地方。

## 职责

`backtrace()` 只能抓**当前调用线程**的栈。上一版用它在后台队列抓「主线程堆栈」，拿到的是采集线程自己的栈——数据长得像真的，却对排查毫无价值。这里提供真正的跨线程回溯：挂起目标线程 → 读寄存器 → 沿帧指针链展开 → 恢复。

## 主要类型

| 类型 | 职责 |
|---|---|
| `PerfBacktraceService` | `PerfBacktraceProviding` 的实现：抓指定线程/主线程/全部线程的栈 |
| `PerfBacktraceProviding` | 栈回溯能力的契约（定义在 Core，采集器可注入假实现） |
| `PerfThreadSnapshot` | 一个线程某一刻的调用栈：帧、寄存器、栈签名 |
| `PerfFrame` | 单帧：地址、镜像名、镜像偏移、符号 |
| `PerfRegisters` | PC / LR / SP / FP |
| `PerfBinaryImage` | 已加载镜像：UUID + ASLR slide，服务端符号化必需 |

## 关键设计

- **主线程端口启动时登记**：经 `pthread_mach_thread_np` 登记一次，所有「抓主线程」「判断是否主线程」都依赖它。不用 `task_threads()[0]`——顺序无保证，挂起错线程后果严重。
- **栈签名基于镜像偏移**：不受 ASLR 影响，跨进程、跨启动稳定，用于把同一处卡顿聚合到一起。
- **帧指针校验**：栈可能被踩坏（我们恰恰在「线程出问题了」时回溯），直接解引用坏 fp 会二次崩溃。带栈边界 + 对齐 + 单调性校验。
- **arm64e 指针认证**：从栈上读出的返回地址带签名，需 `ptrauth_strip` 后才能当地址用。
- **挂起有硬上限**：无论回溯成败都恢复线程，漏掉会让目标线程永久挂起。
- C 层（`CPerfBacktrace`）全部函数保证不分配内存、不加锁——崩溃现场也要能调用。
